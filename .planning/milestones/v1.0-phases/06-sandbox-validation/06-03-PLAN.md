<task type="auto" tdd="true">
  <name>Task 1: Validation report generator and orchestration script</name>
  <files>
    scripts/generate_validation_report.py,
    scripts/run_sandbox_validation.py,
    tests/unit/test_validation_report.py
  </files>
  <behavior>
    - generate_report(log_path, output_path) reads CycleLogEntry list and produces markdown report
    - Report includes: validation period (first/last timestamp), total trading days, total cycles run, trade summary (orders submitted/filled), max drawdown %, final equity RUB, error count, uptime calculation
    - Report shows pass/fail for each criterion: >=5 trading days, <5% max drawdown, >=10 round-trip trades, 0 critical errors (errors_caught that reached cycle-level)
    - Report includes per-day breakdown table: date, cycles, trades, equity, drawdown, errors
    - Report overall verdict: PASS (all criteria met) or FAIL (with failed criteria listed)
    - Empty log file produces a FAIL report with "no data"
  </behavior>
  <action>
    1. Write tests in test_validation_report.py:
       - Test report generation with sample CycleLogEntry data spanning 5 days: verify PASS verdict
       - Test report with less than 5 days: verify FAIL
       - Test report with greater than 5% drawdown: verify FAIL
       - Test report with less than 10 trades: verify FAIL
       - Test report with critical errors: verify FAIL
       - Test empty data: verify FAIL with "no data"
       - Test per-day breakdown table structure

    2. Create scripts/generate_validation_report.py:
       - Import ValidationLogger from src/finalayze/core/validation_logger
       - generate_report(log_path: Path, output_path: Path) -> bool (returns True if PASS)
       - Read entries via ValidationLogger(log_path).get_entries()
       - Group entries by date (from timestamp)
       - Compute: trading_days (unique dates), total_cycles, total_orders, total_fills, max_drawdown, final_equity, total_errors
       - Compute uptime: (last_timestamp - first_timestamp) if greater than 0
       - Build markdown sections: Header, Summary Table, Criteria Assessment, Per-Day Breakdown, Conclusion
       - Write to output_path (default: results/validation/VALIDATION-REPORT.md)
       - CLI: `python scripts/generate_validation_report.py [--log-path X] [--output-path Y]`
       - Uses sys.path.insert for config/src imports (per project convention)

    3. Create scripts/run_sandbox_validation.py:
       - NOT an automated runner (the actual run is 5 days via Docker Compose)
       - Instead, a documented checklist script that:
         a. Prints pre-flight checklist:
            - Verify env vars set (FINALAYZE_TINKOFF_TOKEN, FINALAYZE_MODE=sandbox)
            - Verify Docker running
            - **Verify sandbox account funded with 1,000,000 RUB starting capital** (per user decision: 1M RUB matches Phase 1 assumption and backtested parameters)
            - **Verify only ru_* segments are active in config/segments.py** (per user decision: MOEX-only, no US segments)
            - **Verify bond cycle is enabled** (per user decision: both equity + bond cycles running together for full Phase 5 integration validation)
         b. Prints startup command: `docker compose -f docker/docker-compose.sandbox.yml up -d`
         c. Prints monitoring URLs: Grafana http://localhost:3000, API http://localhost:8000/health
         d. Prints day 2-3 kill test instructions: `docker kill finalayze-app`, verify restart and reconciliation
         e. Prints completion steps: `docker compose -f docker/docker-compose.sandbox.yml logs app > results/validation/docker_logs.txt`
         f. Prints report generation: `python scripts/generate_validation_report.py`
       - Optionally accepts --check-status flag to query /health endpoint and print current status
       - Uses argparse for CLI
  </action>
  <verify>

  </verify>
  <done>
    - generate_validation_report.py produces markdown report with pass/fail assessment
    - Report covers all 4 criteria (days, drawdown, trades, errors)
    - run_sandbox_validation.py prints actionable checklist including 1M RUB capital verification, MOEX-only segment check, and bond cycle enablement check
    - All tests pass
  </done>
