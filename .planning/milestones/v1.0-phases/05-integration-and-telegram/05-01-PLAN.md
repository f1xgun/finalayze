    - Test 1: CRITICAL messages bypass queue and call _send immediately
    - Test 2: IMPORTANT messages are enqueued and drained in priority order (IMPORTANT before INFO)
    - Test 3: Rate limiter blocks when 20 messages sent in last 60 seconds
    - Test 4: 5+ pending fill messages (IMPORTANT) are batched into single digest
    - Test 5: Failed _send gets one retry after 5s delay, then dropped
    - Test 6: Queue drain loop processes messages FIFO within same priority tier
    - Test 7: start() creates drain task, stop() cancels it gracefully
  </behavior>
  <action>
    Create `AlertPriority(IntEnum)` with CRITICAL=0, IMPORTANT=1, INFO=2.
    Create `QueuedMessage` dataclass (order=True) with priority, timestamp, text, parse_mode fields.
    Create `TelegramMessageQueue` class:
    - `__init__(self, alerter: TelegramAlerter)`: stores alerter ref, creates `asyncio.PriorityQueue`, `_sent_timestamps: deque[float]` for sliding window rate limiter, `_drain_task`.
    - `async enqueue(self, text: str, priority: AlertPriority)`: if CRITICAL, call `_send_with_retry()` immediately. Otherwise put `QueuedMessage` on queue.
    - `async _drain_loop(self)`: infinite loop, get from queue, check rate limit (sliding window of `_sent_timestamps` in last 60s), if >=20 sleep until oldest expires, then check batch (if priority==IMPORTANT and queue has 4+ more IMPORTANT items, batch them into digest), call `_send_with_retry()`, record timestamp.
    - `async _send_with_retry(self, text: str, parse_mode: str = "HTML") -> bool`: call `alerter._send()`, if returns False, await asyncio.sleep(5), retry once.
    - `async start(self)`: creates drain task.
    - `async stop(self)`: cancels drain task.
    - `_RATE_LIMIT_PER_MINUTE = 20`, `_BATCH_THRESHOLD = 5`.

    Batching logic: peek at queue, collect consecutive IMPORTANT messages (up to 10), format as single digest: "N fills executed:\n- SBER +10\n- GAZP +5\n..."

    Write tests in `tests/unit/test_telegram_queue.py` using mock TelegramAlerter. Use `asyncio.PriorityQueue` from stdlib per user decision (Claude's Discretion).
  </action>
