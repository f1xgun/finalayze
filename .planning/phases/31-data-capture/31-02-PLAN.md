       ```python
       async def _persist_news_article_async(
           self, article: NewsArticle, impact_result: NewsImpactResult | None,
       ) -> None:
           import hashlib
           from finalayze.core.db import get_async_session_factory
           from finalayze.core.models import NewsArticleModel

           content_hash = hashlib.sha256(article.content.encode()).hexdigest()[:32]
           factory = get_async_session_factory()
           async with factory() as session:
               row = NewsArticleModel(
                   source=article.source[:50],
                   title=article.title,
                   summary=article.content[:500] if article.content else None,
                   url=article.url or None,
                   language=getattr(article, "language", "en"),
                   published_at=article.published_at,
                   symbols=list(impact_result.direct_tickers) if impact_result else [],
                   affected_segments=[s.sector for s in impact_result.affected_sectors] if impact_result else [],
                   scope=impact_result.scope if impact_result and hasattr(impact_result, "scope") else None,
                   raw_sentiment=Decimal(str(round(impact_result.sentiment, 4))) if impact_result else None,
                   credibility_score=Decimal(str(round(impact_result.confidence, 4))) if impact_result else None,
                   is_processed=impact_result is not None,
               )
               session.add(row)
               await session.commit()
       ```

    2. In _analyze_impact_batch, modify _process_one inner function. After successful `result = await analyzer.analyze(article)` and before `self._apply_impact_result(result)`, persist the article:

       ```python
       # Fire-and-forget news article persistence (PERSIST-03)
       ```

       IMPORTANT: _persist_to_db uses _run_async which bridges sync/async. But _process_one is already async. Since _persist_to_db is a sync method calling _run_async, calling it from inside an async context running on the SAME _async_loop will deadlock. Instead, create the DB session directly inline or schedule it differently.

       Solution: Create a dedicated async persist method and call it directly with await inside _process_one (since it's already async), wrapped in try/except for fire-and-forget:
       ```python
       try:
           await self._persist_news_article_async(article, result)
       except Exception:
           from finalayze.api.metrics import db_write_failures
           db_write_failures.labels(table="news_articles").inc()
           _log.warning("db_persist_failed", table="news_articles", exc_info=True)
       ```
