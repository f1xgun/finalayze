Create `alembic/versions/005_sentiment_ml_cagg.py` with:

Header: `from __future__ import annotations`, standard Alembic boilerplate.
`revision = "005"`, `down_revision = "004"`.

`upgrade()` function — three sequential `op.execute()` calls:

1. Convert `sentiment_scores` to a hypertable:
   ```sql
   SELECT create_hypertable('sentiment_scores', 'timestamp',
          migrate_data => TRUE, if_not_exists => TRUE)
   ```
   `migrate_data => TRUE` preserves any existing rows. `if_not_exists => TRUE` is idempotent safety.

2. Create the continuous aggregate view:
   ```sql
   CREATE MATERIALIZED VIEW sentiment_7d_avg
   WITH (timescaledb.continuous) AS
   SELECT
       symbol,
       market_id,
       time_bucket(INTERVAL '1 day', timestamp) AS bucket,
       AVG(composite_sentiment)::numeric(5,4)   AS avg_score,
       COUNT(*)                                  AS article_count
   FROM sentiment_scores
   GROUP BY symbol, market_id, time_bucket(INTERVAL '1 day', timestamp)
   WITH NO DATA
   ```
   Use `composite_sentiment` for `avg_score` (the weighted combination of news + social, most appropriate for ML consumption per research A1 recommendation).
   `WITH NO DATA` defers initial materialization to the first policy execution to avoid a blocking migration.

3. Add the refresh policy:
   ```sql
   SELECT add_continuous_aggregate_policy(
       'sentiment_7d_avg',
       start_offset  => INTERVAL '30 days',
       end_offset    => INTERVAL '1 day',
       schedule_interval => INTERVAL '1 hour',
       if_not_exists => TRUE
   )
   ```
   `end_offset = '1 day'` excludes the incomplete current bucket. `schedule_interval = '1 hour'` keeps the view current.

`downgrade()` function:
- First: `op.execute("DROP MATERIALIZED VIEW IF EXISTS sentiment_7d_avg")` — must drop the dependent cagg before hypertable cleanup.
- Note in a comment: hypertable-to-regular-table conversion is not natively supported. For dev/test with no data, this suffices.

Follow the exact file style of migration 004: `from __future__ import annotations`, `from alembic import op`, type annotations for revision variables, no unused imports.

Do NOT import `sqlalchemy as sa` (not needed — all operations are raw `op.execute()`).
