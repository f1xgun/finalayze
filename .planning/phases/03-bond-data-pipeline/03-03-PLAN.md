    Create src/finalayze/data/bond_discovery.py (Layer 2, data layer) with:

    1. BondDiscoveryService class:
       - __init__(self, fetcher: TinkoffFetcher, registry: InstrumentRegistry)
       - async discover() -> DiscoveryResult:
         a. Call fetcher.fetch_all_bonds() to get all MOEX bonds
         b. Apply filter chain (order matters for efficiency per RESEARCH.md pitfall 6):
            i.   maturity_date > today + 3 months (free, from metadata)
            ii.  risk_level <= 2 (free, from metadata). Use RiskLevel enum values.
            iii. currency == "rub" (free, from metadata)
            iv.  api_trade_available_flag == True (free, from metadata)
            v.   Not perpetual (perpetual_flag == False) -- no maturity date
            vi.  liquidity_flag == True (from T-Invest, primary liquidity filter per user decision)
         c. Classify into segments:
            - ru_ofz: class_code in ("TQOB", "TQOD") or sector contains "government"
            - ru_corporate: everything else that passes filters
         d. For amortizing bonds (amortization_flag=True): fetch amortization schedule
         e. Return DiscoveryResult(ofz=list[BondInfo], corporate=list[BondInfo], filtered_count=int, total_count=int)

    2. DiscoveryResult dataclass:
       - ofz: list[BondInfo]
       - corporate: list[BondInfo]
       - total_count: int (before filtering)
       - filtered_count: int (after filtering)

    3. register_discovered_bonds(result: DiscoveryResult, registry: InstrumentRegistry) -> int:
       - Convert each BondInfo to Instrument with instrument_type="bond"
       - Set segment_id to "ru_ofz" or "ru_corporate"
       - Register in registry
       - Return count of registered bonds
       - Log "bond_discovered" for each bond, "bond_filtered" summary

    4. _bond_proto_to_info(bond_dict: dict) -> BondInfo:
       - Convert T-Invest bond dict to BondInfo schema
       - Map floating_coupon_flag -> floating_coupon, bond_type
       - Map amortization_flag -> amortization_flag, bond_type
       - Determine day_count_convention from class_code (TQOB -> actual/365, etc.)

    IMPORTANT: Per user decision -- include amortizing bonds (track remaining nominal from T-Invest amortization schedule). Include OFZ-IN (inflation_linked). Subordinated bonds get no special treatment (risk_level filter handles them).

    IMPORTANT: Filter order matters (RESEARCH pitfall 6) -- free metadata filters first, then any that require API calls.
