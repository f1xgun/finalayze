       ```yaml
       promtail:
         volumes:
           - ../monitoring/promtail/promtail-config.yml:/etc/promtail/config.yml:ro
           - /var/run/docker.sock:/var/run/docker.sock:ro
           - /var/lib/docker/containers:/var/lib/docker/containers:ro
         # ... rest unchanged
       ```

    2. Add a named volume for Promtail positions persistence and mount it:
       ```yaml
       promtail:
         volumes:
           - ../monitoring/promtail/promtail-config.yml:/etc/promtail/config.yml:ro
           - /var/run/docker.sock:/var/run/docker.sock:ro
           - /var/lib/docker/containers:/var/lib/docker/containers:ro
           - promtail_positions:/positions
       ```

    3. Add `promtail_positions:` to the top-level `volumes:` section (after `loki_data:`).

    **In monitoring/promtail/promtail-config.yml:**

    4. Change positions file path from `/tmp/positions.yaml` to `/positions/positions.yaml` (persisted volume):
       ```yaml
       positions:
         filename: /positions/positions.yaml
       ```

    5. Add `__path__` relabel from docker_sd_configs. The `docker_sd_configs` provides `__meta_docker_container_log_path` label that must be mapped to `__path__` for Promtail to know which file to tail. Add this to `relabel_configs`:
       ```yaml
       relabel_configs:
         - source_labels: ['__meta_docker_container_name']
           regex: '/(.*)'
           target_label: 'container'
         - source_labels: ['__meta_docker_container_log_path']
           target_label: '__path__'
       ```

    6. Remove `event` from labels (high cardinality -- 50+ unique values would create too many Loki streams). Keep only `level` and `container`:
       ```yaml
       pipeline_stages:
         - json:
             expressions:
               event: event
               level: level
               timestamp: timestamp
         - labels:
             level:
         # event is parsed but NOT used as label -- query it via | json | event="..."
       ```

    7. Fix the drop stage for health/metrics endpoints. The current regex `^INFO:.*` does not match JSON logs. Replace with a JSON-aware match+drop using parsed fields:
       ```yaml
       pipeline_stages:
         - json:
             expressions:
               event: event
               level: level
               timestamp: timestamp
               path: path
               method: method
         - labels:
             level:
         - match:
             selector: '{level="info"}'
             stages:
               - drop:
                   source: path
                   expression: "^/(metrics|api/v1/health)$"
                   drop_counter_reason: "health_metrics_noise"
       ```

       If the structlog JSON output does not include `path` and `method` fields for access logs (uvicorn access logs may be separate), use a simpler approach: drop lines containing "/metrics" or "/api/v1/health" via regex on the raw log line:
       ```yaml
       - match:
           selector: '{container="finalayze-sandbox-app"}'
           stages:
             - drop:
                 expression: '(/metrics|/api/v1/health)'
                 drop_counter_reason: "health_metrics_noise"
       ```

    8. Add timestamp stage to use the app's timestamp instead of ingestion time:
       ```yaml
       - timestamp:
           source: timestamp
           format: "2006-01-02T15:04:05.000Z"
           fallback_formats:
             - "2006-01-02T15:04:05Z07:00"
       ```
       Note: Go time format reference (Promtail uses Go). Place this after the json extraction stage.

    **In monitoring/loki/loki-config.yml:**

    1. Add `retention_period` under `limits_config` for 30-day log retention:
       ```yaml
       limits_config:
         allow_structured_metadata: true
         volume_enabled: true
         retention_period: 720h  # 30 days
         ingestion_rate_mb: 10
         ingestion_burst_size_mb: 20
         max_streams_per_user: 5000
       ```

    2. Add `compactor` config to enable retention enforcement. Without a compactor, `retention_period` is ignored:
       ```yaml
       compactor:
         working_directory: /loki/compactor
         compaction_interval: 10m
         retention_enabled: true
         retention_delete_delay: 2h
         retention_delete_worker_count: 150
         delete_request_store: filesystem
       ```

    3. Verify the `storage_config` / `common.storage` section has the filesystem paths set correctly. The current config uses `common.path_prefix: /loki` with `filesystem.chunks_directory: /loki/chunks` and `rules_directory: /loki/rules`. The compactor needs `/loki/compactor` which is under the same prefix -- no additional volume needed.

    The final loki-config.yml should look like:
    ```yaml
    auth_enabled: false

    server:
      http_listen_port: 3100

    common:
      path_prefix: /loki
      storage:
        filesystem:
          chunks_directory: /loki/chunks
          rules_directory: /loki/rules
      replication_factor: 1
      ring:
        kvstore:
          store: inmemory

    schema_config:
      configs:
        - from: 2020-10-24
          store: tsdb
          object_store: filesystem
          schema: v13
          index:
            prefix: index_
            period: 24h

    limits_config:
      allow_structured_metadata: true
      volume_enabled: true
      retention_period: 720h
      ingestion_rate_mb: 10
      ingestion_burst_size_mb: 20
      max_streams_per_user: 5000

    compactor:
      working_directory: /loki/compactor
      compaction_interval: 10m
      retention_enabled: true
      retention_delete_delay: 2h
      retention_delete_worker_count: 150
      delete_request_store: filesystem

    ruler:
      alertmanager_url: http://localhost:9093
    ```
